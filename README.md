# Business Entity Resolution at Scale (Amazon ML Challenge 2026)

**Team "Annie are you okay"**: Rhuthvija Allavala, Vennela Indukuri

This project matches ~1.7M reference businesses (Source 1) to their noisy copies among ~10M records in two other sources (Source 2/3), across the US, India and France. The records include typos, reordered words, abbreviations, Indic scripts, look-alike decoys and a country never seen in training. The pipeline was built in the 72-hour Amazon ML Challenge 2026 hackathon on Unstop.

| Version | What changed | Public leaderboard (macro F0.5) |
|---|---|---|
| v1 | composite-key blocking + LightGBM | 0.954 |
| v2 | asymmetric blocking, coverage/IDF features | 0.965 |
| v3 | 4-gram blocking, stage-2 "what differs" model | 0.972 |
| v3 + | label-free scores for unseen (French) words | 0.973 |
| **v5** | **+ fine-tuned MiniLM cross-encoder, blended** | **0.979** |

Round 2 of the cross-encoder (`colab/ber_cross_encoder_round2.ipynb`) was an experiment. It was slightly better on held-back data but scored 0.978 on the leaderboard, so it is not used in the final pipeline.

The full write-up is in [METHODOLOGY.md](METHODOLOGY.md). The competition data is not included (see the challenge's terms).

# Business Entity Resolution: reproducible pipeline

For every Source 1 business, this pipeline finds the matching Source 2 and Source 3 records.
It writes the two submission files:

- `matching_results.tsv`: the final matches (the file scored on the leaderboard)
- `candidate_pairs.tsv`: the blocking candidates the model scored (every match is also a candidate)

The pipeline uses only the provided training/test data. It makes no external lookups, APIs, geocoding or internet data. The models are three LightGBM classifiers (MIT license) and one small cross-encoder fine-tuned from `cross-encoder/ms-marco-MiniLM-L-12-v2` (Apache-2.0, 33M parameters), all far below the 8B parameter limit.

## Run

`<dataset_dir>` is the challenge `dataset/` folder, which contains `train/` and `test/`.

```bash
# full reproduction: learn dictionary -> normalise -> block -> features -> train -> predict
bash run_pipeline.sh <dataset_dir> <output_dir> [work_dir]

# inference only, reusing the shipped artifacts/ (dictionary, noise vocabulary, both models)
SKIP_TRAIN=1 bash run_pipeline.sh <dataset_dir> <output_dir> [work_dir]
```

Example, from the challenge's `student_resource/` folder:

```bash
bash code/business_entity_resolution/run_pipeline.sh dataset output
python3 utils/validate_submission.py --matching output/matching_results.tsv \
    --candidate output/candidate_pairs.tsv --test-dir dataset/test
```

## Resources

The pipeline was developed on a 2-core machine with 8 GB RAM. The full run takes about 6 hours there, and inference only takes about 2 hours. It needs about 30 GB of free disk for the work directory (DuckDB spill files and feature parquet files).

Knobs (environment variables):

- `THRESHOLD` (default `0.775`): final decision threshold
- `DUCK_MEM` (default `4GB`): DuckDB memory limit
- `NCHUNK` (default `32`): number of feature chunks
- `MAX_TRAIN_ROWS` (default 7M): stage-1 training sample

All randomness (fold split, sampling, LightGBM) uses fixed seeds.

## Method in one paragraph

1. Names and addresses are normalised. This covers Indic-script words (via a dictionary learned from the training matches), digit-for-letter noise, ID tags and phone numbers, legal forms, street abbreviations, state names, unit and mailbox numbers, and house-number ranges.
2. Blocking builds *composite* rare keys: pairs of rare name words, 4-letter name fragments, street words and house numbers. This keeps 97.4% of true matches.
3. A stage-1 LightGBM scores every candidate on 47 similarity features. Pairs with p1 ≥ 0.01 (3.9 per S1 entity) form the final candidate set.
4. A stage-2 LightGBM re-scores them with group evidence (siblings, twins, competing S1 entities) and "what differs" features (noise-word scores, edit types). Words never seen in training, such as French words, get their noise scores estimated from the test pairs *without labels*, using stage-1 probabilities as soft labels.
5. Stage 3 (optional, needs a GPU): a MiniLM cross-encoder reads the two records' romanised text side by side. It is fine-tuned on 2.8M training candidate pairs for 70 minutes on a Colab T4, and its score is blended with the stage-2 probability by a small LightGBM fitted on a separate 15% holdout of S1 entities. On that holdout macro F0.5 goes from 0.9816 (stage 2) to 0.9874. Steps are listed in `run_pipeline.sh`.
6. Each S2/S3 record is assigned to at most one S1 entity, the one with the highest probability, if that probability is ≥ `THRESHOLD` (0.775 without stage 3, 0.75 with it). Out-of-fold macro F0.5 on the training set is 0.981 without stage 3.
